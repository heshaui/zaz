# 多机台目录与草莓猫舍设计

## 目标

在现有可玩版本上增加第二台娃娃机，并建立后续继续扩充机台所需的统一结构。第一台保留为“月亮兔仓”，第二台为“草莓猫舍”。玩家在首页、尚未投币时可以左右选择机台；进入一轮游戏后不能切换。

本阶段交付两台可独立展示、独立保存轮次的机台，不改变现有投币、操作机械爪、结算、兑换和音效流程。

## 已确认的产品规则

- 月亮兔仓每批 8 只，全部使用兔子模型，不混入其他动物。
- 草莓猫舍每批 8 只，全部使用猫咪模型，不混入其他动物。
- 草莓猫舍采用珊瑚红、浅粉、青色的外观，增加猫耳顶棚、猫爪灯牌，以及草莓和毛线球背板。
- 两台机共用游戏币、普通娃娃总数、精品收藏、单次价格、兑换数量和最大幸运次数。
- 每台机独立保存当前幸运轮次、随机目标轮次、布局序号和剩余娃娃数量。
- 只有首页且当前没有已投币轮次时可以切换机台。
- 每批 8 只全部获得后才自动补充下一批；普通情况下不逐只补充。
- 两台机使用相同的内部机械结构和运行节点约定，外壳和普通娃娃种类可以不同。

## 不在本阶段实现

- 不增加小狗、小牛专属机台。
- 不增加刷新道具、机台解锁、机台等级和付费差异。
- 不调整现有兑换规则、幸运规则和价格配置入口。
- 不为不同颜色的普通娃娃设置不同价值。
- 不同时在场景中常驻两台完整机台。

## 机台目录

纯数据层增加统一的 `MachineDefinition`，由首页、存档和运行层共同使用。目录不直接引用 Cocos 类型，便于单元测试。

```ts
export type DollSpecies = 'rabbit' | 'cat';

export interface MachineDefinition {
  id: 'moon-rabbit' | 'strawberry-cat';
  name: string;
  modelKey: string;
  dollTemplateName: 'DollRabbit' | 'DollCat';
  dollSpecies: DollSpecies;
  batchSize: number;
  layoutSeed: number;
  leftAccent: string;
  rightAccent: string;
}
```

目录首期固定包含以下两项：

| 机台 ID | 名称 | 模型键 | 普通娃娃模板 | 每批数量 | 主色 |
| --- | --- | --- | --- | --- | --- |
| `moon-rabbit` | 月亮兔仓 | `moon-rabbit-model` | `DollRabbit` | 8 | 青色、粉色 |
| `strawberry-cat` | 草莓猫舍 | `strawberry-cat-model` | `DollCat` | 8 | 珊瑚红、浅粉、青色 |

`modelKey` 只用于连接纯数据目录和场景资源绑定，不依赖资源文件名。以后调整文件位置时，不需要改存档内容。

## 模型与资源结构

Blender 工程输出两份独立 GLB：

- `game/assets/models/machines/moon-rabbit.glb`
- `game/assets/models/machines/strawberry-cat.glb`

两份模型都必须包含以下稳定节点：

- `MachineRoot`
- `ClawCarriage`
- `ClawHub`
- `ClawCable`
- `ClawArm_0`、`ClawArm_1`、`ClawArm_2`
- `PrizeChuteTarget`
- `PrizeChuteEntry`
- `Dolls`

月亮兔仓只导出 `DollRabbit` 普通模板，草莓猫舍只导出 `DollCat` 普通模板。精品展示模型仍由现有收藏界面负责，不放入普通娃娃批次。

草莓猫舍复用机械爪、轨道、出口和玻璃结构的尺寸与节点名称；外壳单独制作猫耳顶棚、猫爪灯牌、草莓背板和毛线球装饰。这样运行逻辑不需要为第二台机分叉，同时又能明显区分两台机。

单份 GLB 的目标大小不超过 4 MB、三角面不超过 80,000；两份合计不超过 8 MB。构建时只有当前机台的实例留在场景中，避免两套完整模型长期同时渲染。

## Cocos 资源绑定

运行组件新增可在编辑器中配置的 `MachineAssetBinding[]`：

```ts
@ccclass('MachineAssetBinding')
export class MachineAssetBinding {
  @property
  modelKey = '';

  @property(Prefab)
  prefab: Prefab | null = null;
}
```

`PrototypeCoordinator` 不再只有单个 `machinePrefab`，而是先通过机台 ID 找到目录项，再通过目录项的 `modelKey` 找到对应绑定。启动时使用存档中的 `selectedMachineId`；没有有效选择时使用目录第一项“月亮兔仓”。

候选模型先在当前模型旁边创建并检查全部必需节点。只有检查通过，才会绑定机械爪、娃娃根节点和出口节点，然后替换旧模型。缺少资源、创建失败或节点不完整时，旧模型和旧选择都保持不变。

## 首页切换流程

首页左右按钮发起候选选择，而不是立即改写已选索引：

1. `HomePanel` 根据方向计算候选机台，并暂时锁住两个切换按钮。
2. `GameUiRoot` 调用 `PrototypeCoordinator.selectMachine(machineId, direction)`。
3. 运行层确认当前为未投币的空闲状态，再创建和校验候选模型。
4. 新模型从切换方向一侧轻微移入，旧模型向另一侧轻微移出，持续约 `0.18` 秒。
5. 动画不改变镜头距离、不缩放模型；结束后销毁旧模型，只保留新模型。
6. 成功后首页才更新名称、颜色、位置和剩余数量；失败则恢复按钮，界面仍显示原机台。

切换期间不接受再次切换、投币或进入收藏界面的操作，避免状态和模型不同步。动画期间允许两台实例短暂共存，结束后必须只剩当前机台。

## 玩家状态与存档升级

存档格式升级为第 3 版，分为共享数据和按机台保存的数据：

```ts
export interface MachineRuntimeState {
  progress: number;
  strongTarget: number;
  layoutSequence: number;
  remainingDolls: number;
}

export interface PrototypePlayerState {
  coins: number;
  ordinaryDolls: number;
  premiumDolls: Record<string, number>;
  selectedMachineId: string;
  machines: Record<string, MachineRuntimeState>;
}
```

`PrototypeStore` 是共享数据与机台数据的唯一修改入口。投币扣除共享游戏币；获胜增加共享普通娃娃数，同时只减少当前机台的剩余数量。当前机台一批清空后，关闭结果界面时把该机台的 `layoutSequence` 加一，并把 `remainingDolls` 恢复为目录中的 `batchSize`。

切换机台时，幸运进度不会互相带入。切回某台机后，继续该机上次保存的 `progress` 和 `strongTarget`。布局使用“机台基础种子 + 布局序号”生成；重新进入机台时保持同一批次的数量与可重复布局，不保存每只娃娃的即时翻滚角度。

第 1、2 版旧存档按以下规则升级：

- 游戏币、普通娃娃和精品收藏完整保留。
- 原有幸运进度和随机目标轮次归入月亮兔仓。
- 月亮兔仓默认剩余 8 只、布局序号为 0。
- 草莓猫舍创建全新轮次，默认剩余 8 只、布局序号为 0。
- 当前选择设为月亮兔仓。
- 升级后的数据在正常启动后写回第 3 版。

遇到当前目录中不存在的机台 ID 时，该项暂不参与游戏，但只要字段有效就原样保留；同时按目录为缺失的在架机台补充默认状态。这样机台临时下架后，玩家已有进度不会丢失。

## 运行状态约束

`PrototypeCoordinator.selectMachine()` 只在以下条件全部满足时执行：

- 当前轮次状态为 `idle`。
- 状态层的投币轮次为 `waiting`。
- 结果窗口、确认窗口和补充窗口均未打开。
- 没有另一段机台切换动画正在进行。

任一条件不满足时返回 `false`，不改变界面、存档或场景。投币成功后，当前机台 ID 固定到本轮结算完成；即使通过其他调用路径请求切换，也会被运行层拒绝。

## 娃娃批次

创建机台时，运行层只选择目录指定的模板，并按当前机台的 `remainingDolls` 创建普通娃娃。颜色仍从统一配置中选择，所有普通娃娃价值相同。

每次获胜只隐藏本次进入出口的娃娃，不立刻补充。当剩余数量变为 0 时，结果数据带出 `needsRefill: true`；关闭结果界面后才生成下一批 8 只，并保存新的布局序号。切换机台不会触发补充。

## 代码边界

- `home-machine-selection.ts`：机台目录、首页展示数据、左右循环选择。
- `prototype-save.ts`：第 3 版格式、旧格式升级、输入校验。
- `prototype-store.ts`：共享资产、当前机台、各机台独立轮次和批次数量。
- `machine-asset-binding.ts`：Cocos 编辑器中的机台 ID 与预制体连接。
- `prototype-coordinator.ts`：候选模型校验、切换动画、运行节点重新绑定、娃娃创建。
- `home-panel.ts`：候选选择、按钮锁定、成功后更新首页。
- `game-ui-root.ts`：连接首页操作、运行层选择结果和窗口状态。
- Blender 生成脚本：生成两套外壳并分别导出模型与预览图。

不在本阶段拆分与多机台无关的现有模块，也不改变机械爪动作实现。

## 异常处理

- 找不到机台目录项：拒绝切换，保留当前机台。
- 找不到资源绑定或绑定为空：拒绝切换，保留当前机台。
- 候选模型缺少必需节点：销毁候选实例，保留当前机台。
- 切换动画中页面退出：立即结束动画并保留最后一次完整激活的机台。
- 本地保存不可用：当前游戏继续运行，内存状态不退回。
- 存档部分机台数据异常：共享数据有效时，只重建异常机台的默认状态。
- 存档共享数据异常：整份存档视为无效，使用现有初始配置。

## 测试与验收

自动测试覆盖：

- 首页目录包含两台机，左右切换可循环，名称、主题色和位置正确。
- 第 1、2 版存档升级后共享数据不变，旧幸运进度进入月亮兔仓。
- 两台机的幸运进度、随机目标、布局序号和剩余数量互不影响。
- 投币后以及切换动画中，机台选择请求被拒绝。
- 获胜只减少当前机台数量；8 只全部获得后才补充下一批。
- 月亮兔仓只创建兔子，草莓猫舍只创建猫咪。
- 两份 GLB 都包含稳定运行节点，且各自符合模型大小和三角面预算。
- 候选资源或节点异常时，当前机台和首页选择不改变。
- 现有投币、操作、结算、兑换、镜头和音效测试继续通过。

手动验收由 Cocos 预览完成：

- 首页可在两台机之间平滑横向切换，画面不闪烁、不突然放大。
- 草莓猫舍外观与月亮兔仓明显不同，同时机械爪与出口位置保持正常。
- 两台机内分别只出现 8 只兔子或 8 只猫咪。
- 在一台机投币后，不能通过任何首页操作切到另一台机。
- 两台机分别进行若干轮后重新进入，余额和收藏共用，幸运进度与剩余数量分别恢复。

## 完成标准

- 首页能稳定选择月亮兔仓和草莓猫舍。
- 两套模型符合确认的外观与单一动物规则。
- 切换过程约 `0.18` 秒，仅做轻微横向过渡，不缩放镜头。
- 共享资产和独立机台状态在重启后正确恢复。
- 一批 8 只全部获得后才补充。
- 全部自动测试与 TypeScript 检查通过。
- 不进行版本提交操作。
