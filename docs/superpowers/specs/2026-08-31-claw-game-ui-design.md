# 星愿抓抓屋 UI 设计说明

日期：2026-08-31  
状态：设计已确认，等待实施计划

## 1. 背景与目标

现有版本已经完成投币、移动、下爪、结算、整批补充、收藏兑换和本地保存，首版核心玩法已经走通。本阶段只重做游戏界面与页面组织，不改变已经确认的玩法规则。

本次 UI 改造的目标：

- 建立轻量加载页、单机台首页、游戏操作页、收藏兑换页和每局结果层。
- 让界面像娃娃机实体控制台的一部分，而不是网页导航与卡片的组合。
- 使用竖屏 9:16，适合手机单手操作。
- 保留三维机台作为主视觉，页面切换时不重复载入机台。
- 保留费用、兑换数量和每批娃娃数量的动态配置能力。
- 不展示爪子力度、隐藏目标或相关进度。

## 2. 已确认的产品决定

- 游戏名称为“星愿抓抓屋”。
- 首页直接展示当前单台娃娃机，首版不做多机台大厅。
- 投币后才显示摇杆与下爪按钮。
- 收藏与精品兑换合并为一个页面。
- 普通娃娃价值相同，兑换时只计算普通娃娃总数，可混合使用。
- 每局结果覆盖在当前游戏画面上，不跳转到独立场景。
- 获得最后一只娃娃后，先完成本局结果；关闭结果层时再整批补充 8 只。
- 再来一局必须重新投币，不自动连续扣费。
- 使用 TypeScript；较难理解的逻辑添加中文注释。
- 不调整本机 Node 环境。

## 3. 首版范围

### 3.1 包含

- 轻量加载页
- 单机台首页
- 游戏操作界面
- 每局结果层
- 收藏与兑换页
- 整批补充过渡
- 竖屏短屏与长屏适配
- 界面所需的基础图标、灯牌、按钮与字体资源

### 3.2 暂不包含

- 多机台大厅
- 游戏币购买流程
- 每日任务、签到、排行和活动页
- 后台运营界面
- 多套主题皮肤
- 娃娃详情与稀有度区分

## 4. 场景结构

采用混合结构。

### 4.1 Boot.scene

轻量启动场景，只包含品牌灯牌、加载表现、进度显示与重新加载按钮。它预载主场景，完成后进入 `prototype.scene`。

### 4.2 prototype.scene

继续作为首版主场景，保留现有机台、爪子、娃娃、相机和脚本引用。首页与游戏页共用同一套三维内容，只切换相机参数与 UI 层，不重新创建机台。

### 4.3 覆盖层

以下内容都位于主场景 UI 根节点下：

- `HomePanel`：首页信息与投币入口
- `GameConsole`：摇杆、下爪、视角与操作提示
- `ResultOverlay`：本局结果与后续操作
- `CollectionOverlay`：普通娃娃数量、精品陈列与兑换确认
- `RefillOverlay`：整批补充期间的短过渡

收藏页和结果层不卸载主场景。关闭后回到同一台机台的正确状态。

## 5. 页面流程

```text
加载页
  -> 单机台首页
  -> 投币
  -> 游戏操作
  -> 本局结果
       -> 再来一局：回到首页并等待再次投币
       -> 去兑换：打开收藏兑换页
       -> 关闭：回到首页
```

收藏兑换页也可从首页侧边功能键进入。若最后一只娃娃已被获得，关闭结果层时先进入整批补充过渡，完成后再恢复首页待机。

## 6. 视觉系统

### 6.1 画布与布局基准

- 设计分辨率：`720 x 1280`
- 屏幕方向：竖屏 9:16
- 适配原则：操作台尺寸稳定，三维展示区吸收屏幕高度差
- 手机安全区域：顶部信息与底部操作区均避开系统区域

超长屏增加机台玻璃区的可见高度；较短屏压缩三维展示区，但不缩小摇杆、下爪按钮和主要文字。

### 6.2 颜色

| 角色 | 色值 | 用途 |
| --- | --- | --- |
| 机台青 | `#15B8BE` | 机台灯带、视角按钮、次级高亮 |
| 珊瑚红 | `#EF607D` | 投币、下爪和主要操作 |
| 明黄 | `#FFC83D` | 游戏币、费用、奖励和重点提示 |
| 奖品紫 | `#7764B2` | 精品区、品牌灯牌与收藏入口 |
| 深墨色 | `#18242E` | 轮廓、控制台底座与主要文字 |
| 玻璃白 | `#F8FBFC` | 浅色文字、计数器和高光 |

颜色主要出现在机台灯牌、控制台、实体按钮和计数器中。三维机台与娃娃始终是画面主体，不使用大面积单色背景覆盖游戏内容。

### 6.3 字体

- 游戏名称：制作独立美术字资源，呈现电玩城顶部灯牌质感。
- 按钮与提示：使用宽而醒目的粗体中文。
- 游戏币、数量与费用：使用窄体粗数字，模拟机台电子计数器。
- 固定文字：优先制作小型字体图集，保证不同平台效果一致并控制资源体积。
- 后续新增的动态中文名称：使用项目内统一中文字体作为补充。

### 6.4 形状与材质语言

- 主要按钮采用圆形实体按键、深色硬边框和短距离投影。
- 首页信息嵌入灯牌、票券槽和电子计数器。
- 收藏页采用电玩城奖品陈列柜与分层货架。
- 不使用顶部导航栏、悬浮网页卡片或成组的胶囊按钮。
- 圆角仅用于确实需要柔和触感的小面积元素，机台框架保持硬朗。

### 6.5 标志性动效

首页到游戏页使用一段连贯动作：

```text
投入硬币 -> 控制台灯依次点亮 -> 相机靠近机台 -> 摇杆与下爪按钮启用
```

其他位置仅保留短促按压、灯光反馈和结果层进入效果，不堆叠无关动画。

## 7. 页面设计

### 7.1 加载页

- 中央显示“星愿抓抓屋”灯牌。
- 灯牌随着真实加载进度逐步点亮。
- 机台内部灯光随后亮起，完成后自然进入首页。
- 加载未完成时显示重新加载入口，不进入空白主场景。

### 7.2 单机台首页

- 三维娃娃机占据主要区域，完整展示机台与当前 8 只娃娃。
- 游戏币显示为机台电子计数器。
- 收藏显示为机台侧边功能键；设置页不进入首版范围。
- 当前费用显示在控制台票券槽中。
- 底部主按钮显示“投入 N 币”，其中 N 来自动态配置。

### 7.3 游戏操作页

- 投币完成后，相机平滑靠近操作台。
- 左侧为固定尺寸摇杆，右侧为固定尺寸下爪按钮。
- 视角按钮仅在选择落点阶段可用。
- 顶部只保留游戏币、普通娃娃总数和返回按钮。
- 界面不显示爪子力度、隐藏目标或周期进度。
- 下爪开始后，摇杆、视角和返回按钮暂时锁定，直到完整动作结束。

### 7.4 本局结果层

- 保留三维机台作为背景，覆盖层只占据画面中下部。
- 获得娃娃：展示娃娃形象、获得数量和“再来一局”。
- 未获得娃娃：展示简短结果和“再来一局”。
- 达到兑换数量：增加“去兑换”。
- 结果层出现前，娃娃应完成落下、弹起、翻身并稳定。

### 7.5 收藏与兑换页

- 整体表现为电玩城奖品陈列柜。
- 顶部显示普通娃娃总数。
- 精品娃娃按货架分层展示形象、名称和所需数量。
- 普通娃娃不区分类别，兑换只扣除总数。
- 数量不足时精品仍可查看，但兑换按钮不可用。
- 数量足够时选择精品并进行二次确认。

### 7.6 整批补充过渡

- 最后一只娃娃结算后暂时保留空机台。
- 关闭结果层时锁定操作，并播放短暂补充表现。
- 新一批 8 只全部就位后恢复首页和投币按钮。
- 首版不在每获得一只后立即增加一只。

## 8. 交互状态

### 8.1 首页待机

- 显示费用和投币按钮。
- 游戏币不足时按钮变暗，点击只显示余额不足提示。
- 首版不从该提示进入购买流程。

### 8.2 投币完成

- 扣费成功后才进入选择落点阶段。
- 投币完成后才显示摇杆和下爪按钮。
- 此时返回需要二次确认，并明确本局费用不会返还。

### 8.3 选择落点

- 摇杆、下爪与视角按钮可用。
- 操作提示只说明当前可执行动作，不提示本局力度结果。

### 8.4 下爪与结算

- 所有可重复触发的控件暂时锁定。
- 未获得娃娃时，娃娃在允许范围内自然落下并完成物理表现。
- 获得娃娃时，娃娃进入出口后再更新收藏数量。
- 结算和本地保存完成后显示结果层。

### 8.5 再来一局

- 关闭结果层。
- 返回首页待机。
- 不自动扣费，不立即显示摇杆。

## 9. 模块职责

### 9.1 PrototypeCoordinator

继续负责玩法流程、爪子动作、娃娃结果、整批生成与本地保存。UI 不复制这些规则。

需要为整批补充增加明确的可调用入口，使补充动作由结果层关闭时触发，而不是在结果刚产生时立即触发。

### 9.2 GameUiRoot

主场景 UI 总控，职责包括：

- 接收 `PrototypeCoordinator` 的变化通知和本局结果。
- 调用 `hud-presenter` 生成界面显示数据。
- 控制首页、操作台、结果层、收藏层和补充层。
- 统一处理返回与覆盖层优先级。
- 将按钮操作转交给现有协调器。

### 9.3 页面组件

每个页面组件只负责自身节点、动画和按钮，不直接修改玩家数据：

- `HomePanel`
- `GameConsole`
- `ResultOverlay`
- `CollectionOverlay`
- `RefillOverlay`

### 9.4 现有 PrototypeHud 的迁移

现有 `prototype-hud.ts` 同时负责运行时节点创建、图形绘制、状态刷新和按钮逻辑。实施时先保留它作为迁移桥梁，再由 `GameUiRoot` 和页面组件接管职责。

新版主要布局使用场景节点或预制资源，脚本负责状态与动画，不再把整套正式界面全部写成运行时图形绘制。这样可以在 Cocos 编辑器中直接调整位置、图片与字体。

## 10. 数据流

显示方向：

```text
PrototypeCoordinator
  -> PrototypeStore 快照
  -> hud-presenter
  -> GameUiRoot
  -> 各页面组件
```

操作方向：

```text
页面按钮
  -> GameUiRoot
  -> PrototypeCoordinator
  -> Store 与 Session
  -> 保存
  -> 界面刷新
```

`GameUiRoot` 是界面与玩法之间的唯一协调层。页面组件不直接访问存储，也不自行计算费用、兑换结果或本局结果。

## 11. 动态配置

继续由 `MachineConfig` 提供：

- 初始游戏币
- 每局费用
- 完整力度周期上限
- 精品兑换所需普通娃娃数量
- 每批普通娃娃数量，首版为 8

UI 只读取格式化后的显示值。调整每局费用时，首页票券槽与投币按钮同步更新，不需要修改界面资源。

## 12. 异常与边界处理

- 主场景资源未就绪：停留在加载页，提供重新加载。
- 本地数据不存在：使用初始配置建立新数据。
- 本地数据格式较旧：沿用现有兼容逻辑，并在成功读取后保存为当前格式。
- 动态配置超出合理范围：使用经过校验的配置值，不让界面进入不可操作状态。
- 投币期间重复点击：只接受第一次有效操作。
- 下爪期间重复点击：控件锁定，不产生第二条动作序列。
- 兑换数量不足：不扣除普通娃娃，并保持精品可查看。
- 整批补充期间：投币、摇杆、下爪和兑换均不可用。
- 覆盖层同时请求显示：结果层优先，其次为补充层，再其次为收藏层。

## 13. UI 资源组织

建议新增以下目录：

```text
game/assets/ui/
  fonts/
  icons/
  textures/
  prefabs/
  animations/

game/assets/scripts/ui/
  game-ui-root.ts
  home-panel.ts
  game-console.ts
  result-overlay.ts
  collection-overlay.ts
  refill-overlay.ts
  boot-screen.ts
```

图标优先使用统一线宽和填充规则的图片资源。投币、下爪等关键按钮可配合机台颜色制作独立图片，避免通用网页图标感。

## 14. 验证范围

### 14.1 自动验证

- 首页待机、投币完成、操作中和结果层的显示数据。
- 游戏币不足时的按钮与提示。
- 兑换数量不足和足够时的控件状态。
- 最后一只娃娃结算后的整批补充时机。
- 每局费用动态变化后的文字与扣费结果。
- 现有玩法测试保持通过。
- TypeScript 检查通过。

### 14.2 Cocos 内检查

- `720 x 1280` 基准画面不重叠。
- 常见短屏和长屏下，顶部信息与底部操作区不越界。
- 机台在首页和游戏页均完整可见，操作页略微俯视。
- 摇杆、下爪和视角按钮有明确按压反馈。
- 投币过渡、结果层和整批补充顺序正确。
- 收藏页可查看、选择、确认与返回。
- 侧面视角下玻璃保持透明。

## 15. 完成标准

满足以下条件视为本阶段完成：

- 五个首版页面或覆盖层均可正常进入和退出。
- 首页与游戏页共用同一台三维机台，切换时不重复载入。
- 未投币时不显示摇杆与下爪按钮。
- 所有费用显示均来自动态配置。
- 界面不展示力度和隐藏周期信息。
- 普通娃娃按总数进行混合兑换。
- 最后一只娃娃结算后，关闭结果层才补充新的一批 8 只。
- 竖屏布局在目标尺寸下无文字或控件重叠。
- 自动验证与 TypeScript 检查通过。
